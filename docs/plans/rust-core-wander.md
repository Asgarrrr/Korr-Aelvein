# Design: korr-core and wander

The fourth step of the Rust rewrite (`rust-structure.md` §0): the core
`Floor` and its first mechanic, `wander`. Brainstormed with the user on
2026-10-10. Inputs: two research reports (module seams in Rust; creature
decision models), a review of a first draft by Codex `gpt-6-astra`, and an
independent architecture by the same model that never saw this design. The
TS engine is not a spec: every choice comes from the game's needs and Rust
prior art.

## User decisions

- The grid is the only source of an entity's position. There is no
  `Position` component.
- `Floor` owns all the state of one floor: `Store`, `Grid`, scheduler,
  arbitration, event queue, inbox. Each lives in its own file of
  `korr-core`; placement depends on none of the others.
- No decision LOD: every creature decides every time it acts (P = 1). A P
  above 1 comes back only if the Rust bench at target scale (~10k entities
  per floor, ~50 floors) exceeds the budget, and then only behind the
  season-bench fidelity checks. Reason: in TS, every P above 1 shifted at
  least one population, for at most a 2.1x gain (`generative-species.md`).
- Turn semantics: a creature decides then acts, one at a time, on the
  current state. Rejected: all decide on a round snapshot, then resolve in
  order (batchable, but a creature reacts one round late and wastes turns
  near the player). Kept in `docs/ideas.md` if the bench fails.
- Grid follow-ups: `tests/model/driver.rs` is split by subject in its own
  commit. Public terrain readers and an unordered row scan wait for their
  first consumer (`docs/ideas.md`): wander needs neither.

## 1. Components

### Placement (`korr-grid`, used by `korr-core/src/floor/`)

- The grid keeps one canonical record per placed entity: anchor cell,
  `Layer`, footprint (1x1 for now). The cell indexes (`actor`, thing
  lists) derive from these records.
- The records are serialized in the floor image and validated on load:
  two actors on one cell, a cell off the shape or on the ring →
  `Corrupt`. The indexes are rebuilt from them.
- A multi-cell move validates the whole footprint and ignores overlap
  with itself. Footprint changes are atomic.
- `Floor` is the only writer: `spawn_at(at, Layer)`, `despawn(h)` (unlinks
  only a placed entity), `step(h, Dir)`, `pos(h) -> Option<Pos>`,
  `depart` / `arrive`. `pos` is `None` for an entity in flight or
  contained.
- Contexts are built from disjoint field borrows inside `korr-core`, never
  through `&mut self` accessors.

### Module seam

```rust
pub trait Module: Sync + Sized {
    const NAME: &'static str;
    type Config;
    type Action: Copy;                       // tags only, no payload
    fn declare(d: &mut Declare<'_>, cfg: &Self::Config) -> Pending<Self>;
    fn resolve(p: Pending<Self>, r: &Resolve<'_>) -> Result<Self, BuildError>;
    fn tick(&self, _: &mut TickCtx<'_>) {}
    fn propose(&self, _: Actor, _: &Senses<'_>, _: &mut Candidates<'_, Self::Action>) {}
    fn prepare(&self, _: Self::Action, _: &PrepCtx<'_>, _: Actor, _: Target) -> Prepared;
    fn commit(&self, _: Self::Action, _: &mut CommitCtx<'_>, _: Actor, _: Target);
}
```

- Static, no `dyn`. The registry is a struct generated by `modules!` in
  `korr-engine`, in one explicit order, each field an `Option<M>` so a
  scenario disables a module. Core functions are generic over
  `impl Mechanics`; data types never are.
- The trait is extracted at flora. Wander is written against concrete core
  types first; the sketch above is the target shape, not a frozen API.

### Access in types

- A component key carries the id of its schema; using it on another
  schema panics. `ComponentKey<T>` splits into `Own<T>` (not `Clone`,
  minted once, scoped to the module name) and `Read<T>` (`Copy`,
  resolved by name through `contracts`). Writes take `&Own<T>`.
- Build in two phases: every module declares, then every module resolves.
  A contract read is marked required or optional. A required contract
  whose owner is absent or disabled fails the build; an optional one
  resolves to `None` and the actions that need it are never proposed.
- Bulk ticks write through row views: a tick writes the row it iterates.
- Contract types are `Copy`. No state outside columns: callbacks take
  `&self`; the sim `clippy.toml` disallows `core::cell` and
  `core::sync::atomic` types; mechanic crates `#![forbid(unsafe_code)]`.
- A module's RNG stream derives from `M::NAME` inside the core's generic
  call helper. Module names are checked unique at build.

### Actions and effects

- `propose` reads only: `&Senses`, `&mut Candidates`.
- An action runs in two steps. `prepare` reads only and returns
  `Prepared::{Go { cost }, Instead(ActionKey, Target), Blocked, Fail}`.
  `commit` then writes and cannot fail. A write before a failure is
  impossible by construction.
- `commit` writes the module's own components through `CommitCtx`, and
  reaches the rest of the world two ways:
  - Lifecycle primitives, a closed core set: `step`, `harm`, `spawn`,
    `kill`, `emit`. It grows with the core, never with mechanics.
  - Owner commands: a module asks the owner of a contract to change its own
    state (hunger asks flora to consume a plant). The owner validates in
    its `prepare` and applies in its `commit`, in the same action. Both
    happen or neither does.
- An integration adapter in `korr-engine` turns one mechanic's fact into
  another's command when neither should know the other (consumed →
  nourished).
- `Instead` hops are capped per run (`config.rs`); past the cap the run is
  `Fail`.
- Spawn takes a neutral recipe type below `core` and `genome`; `genome`
  and `engine` produce recipes, `core` applies them.

### Decision

- Dual utility. `Band { Routine, Vigilance, Urgent, Reflex }` is owned by
  the core. A `u16` weight orders candidates inside a band.
- Order: band desc, weight (plus inertia for the current intent) desc,
  `ActionKey` asc, `Target` asc. Arbitration takes the maximum, never a
  sum: a new mechanic never shifts existing decisions.
- Inside a module, combine considerations with `min` or a Q8 product, at
  most 3 factors. Curves are integer lookup tables built from config
  points. Genes move a curve input or a weight, never a band.
- The intent is `{ ActionKey, Target }`. `Target` is `None`, an `EntityId`
  or a `Pos`, never a `Handle`. Every action is a registered descriptor:
  key, required components, owner module.

### Perception

- `Senses` is an actor-wide snapshot built by the core before proposals,
  over a fixed sight radius from config. Every proposer reads the same
  facts, whatever the registry order. A floor whose modules read no
  perception skips the scan.
- No version counter: `prepare` revalidates.
- Dijkstra maps are for static goals (stairs, migration), rebuilt on
  terrain change. Not in this delivery.

### Time

- A round has fixed phases:
  1. Environment: every `tick`, reading previous-turn buffers.
  2. Actors: due actors run in `(next_at, EntityId)` order, each deciding
     then acting on the current state.
  3. Lifecycle: buffered kills, spawns and drops settle in a stable order.
  4. Barrier: departures leave, arrivals land. Arrivals and newborns act
     next round, so floor order never changes a result.
- Every attempt consumes time: `Go` costs its `cost`, `Blocked`, a second
  `Fail` and "no candidate" cost one idle (`config.rs`, at least 1 tick).
  The clock uses checked arithmetic. A dead or departed actor leaves the
  schedule.
- A player is an actor whose decision comes from an input. The floor stops
  in phase 2 when a player is due and the server has no input.

### Randomness

- A cell subject includes the floor: `Subject::Cell` packs floor and
  cell index, so the same cell of two floors draws differently.
- Draw purposes inside one module are permanent indexes.

### Stable names and saves

- Module `wander`, action `wander/roam`, component `wander.<name>`: ASCII,
  lowercase, frozen once shipped. `ActionKey` is a const hash of its name;
  a collision panics at build.
- A save loads only under the same ruleset: the floor image carries a
  fingerprint of module names, action keys and component names, and load
  refuses a mismatch. Migration is a later, explicit tool.
- Saves happen at a round barrier. The image holds the store, placement
  records, terrain, intents, `next_at`, the round counter and the inbox.

### Wander (`sim/biology/ethology/wander/`, `korr-wander`)

- Proposes `roam` in band `Routine` at its config weight.
- `roam` is a goal action. `prepare` draws a direction keyed by (actor,
  round) and checks the step; a refused step is `Blocked`. `commit`
  requests `step`. It never caches a target cell.
- Removing wander leaves creatures that idle.

## 2. Errors

- Illegal step: `StepError` in `prepare` → `Blocked`. The game goes on.
- `Fail`: arbitration runs once more without that action; a second `Fail`
  idles.
- Missing required component: `Fail`, never a panic.
- Load: untrusted bytes never panic. Bad placement → `Corrupt`; ruleset
  mismatch → a typed error.
- A broken core invariant (link of a linked slot, a key on another schema)
  panics naming it.

## 3. Tests (in `sim/scenarios` unless noted)

- Wander: a seeded floor, N rounds; creatures spread and never share a
  cell.
- A trapped wanderer (walled in) still advances the clock: the round
  ends.
- Determinism: same seed → same world hash; pinned.
- Two floors with travel: swapping floor processing order keeps the hash.
- Wander disabled: the game runs, creatures idle.
- Save at a barrier, reload, replay: same hash as the uninterrupted run.
- A changed ruleset refuses the save.
- `Instead` loop: a fake module that answers `Instead` to itself ends in
  `Fail` at the cap.
- Tie order: equal band and weight resolve by `ActionKey`, whatever the
  registry order.
- Two-phase build: a reader registered before its owner resolves; a
  missing required owner fails the build.
- A key from another schema panics (`korr-ecs` test).
- Benches: one full decision at P = 1 and one wander turn; a round at
  target scale against ~200 ns per entity.

## 4. Changes to existing documents

- `rust-grid.md` §1–2, `occupancy.rs` and `image.rs` doc comments: the
  grid's placement records are the source of position, saved in the floor
  image.
- `CLAUDE.md`, engine invariants: replace the decision-LOD rule with the
  P = 1 rule, and add the round phases. Needs the user's approval.
- `docs/ideas.md`: terrain readers, unordered row scan, decision LOD,
  snapshot-decision turns.

## 5. Seam order

- Wander: schema-bound keys and `Own`/`Read` in `korr-ecs`, placement
  records, `Senses`, prepare/commit, intents, scheduler with round phases,
  save at the barrier, two-floor travel.
- Flora: extract `Module`, `Mechanics`, `modules!`; cell fields with their
  previous-turn buffer; the environment phase.
- Hunger: first `Read<T>` and the first owner command (consume a plant),
  `harm`. Freeze the core API only once both work.

## Prior art

- Static system trait with `const NAME`: veloren `common_ecs::System`.
- Runtime access checks we avoid: Bevy B0001, shipyard `InvalidSystem`.
- Open effect enums that became bottlenecks: bracket-lib `EffectType`
  (ch. 67), veloren `ServerEvent` (devblog 93).
- Alternate action: Nystrom, "A Turn-Based Game Loop".
- Dual utility: Dill and Mark, GDC "Improving AI Decision Modeling
  Through Utility Theory"; IAUS rejected (floats, nth root, rules in data).
- Addressed randomness: Random123. Cross-platform determinism tests:
  Factorio FFF-370.
- Dissent: LogLog Games on borrow-checker refactors and split logic.
